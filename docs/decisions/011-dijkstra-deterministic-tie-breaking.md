# 011. Dijkstra의 동일 비용 경로를 Edge ID 순서로 결정

- 상태: 채택
- 결정일: 2026-08-20

## 맥락

같은 최단거리를 가진 Path가 여러 개면 collection이나 DB 조회 순서에 따라 Dijkstra 결과가 달라질 수 있다. 같은 Map과 입력으로 실행한 simulation은 항상 같은 Path를 얻어야 한다.

## 결정

`DijkstraPathPlanner`는 후보 Path를 다음 순서로 비교한다.

1. 누적 `distanceMeters`의 정확한 `Double` 값
2. 전체 `EdgeId` 목록의 사전식 순서

`EdgeId`는 UUID의 안정적인 natural order를 사용한다. Outgoing Edge도 `EdgeId` 순으로 정렬하며, 같은 비용으로 Node에 도달한 경우 먼저 발견한 Path가 아니라 전체 Edge ID 목록이 앞선 Path를 유지한다.

| 항목 | 결정 |
| --- | --- |
| 1차 기준 | 누적 `distanceMeters` |
| 동률 판단 | 정확한 `Double` 비교 |
| 2차 기준 | 전체 `EdgeId` 목록의 사전식 순서 |
| 입력·순회 순서 | 결과에 영향 없음 |
| Edge 개수 | 별도 우선순위로 사용하지 않음 |
| Random | 사용하지 않음 |

## 선택의 장점

| 관점 | 장점 |
| --- | --- |
| 재현성 | 같은 immutable Map과 입력은 항상 같은 Path를 반환한다. |
| Parallel edge | 동일 Node를 잇는 Edge도 정확하게 순서를 결정한다. |
| 정책 분리 | Edge 개수 같은 숨은 2차 최적화 기준을 추가하지 않는다. |
| 비교 안정성 | Epsilon으로 인한 비일관적인 정렬을 피한다. |

## 감수하는 단점

| 단점 | 대응 |
| --- | --- |
| UUID 순서는 물류상의 우선순위를 의미하지 않는다. | 동일 비용 결과를 고정하기 위한 기술적 기준으로만 사용한다. |
| 전체 Edge ID 목록 비교 비용이 든다. | 초기 Map 규모에서는 단순성과 재현성을 우선하고 실제 병목일 때 최적화한다. |
| 부동소수점의 작은 차이도 다른 비용으로 취급한다. | 정확한 소수 동률이 필요하면 epsilon 대신 거리 표현 타입을 재검토한다. |

## 검토한 대안

| 대안 | 장점 | 선택하지 않은 이유 |
| --- | --- | --- |
| 입력 또는 발견 순서 | 구현이 가장 단순하다. | Collection과 DB 조회 순서에 따라 결과가 달라진다. |
| Edge 개수가 적은 Path | 경로가 단순해 보인다. | 거리 외의 2차 최적화 정책을 암묵적으로 추가한다. |
| Node ID 순서 | Node 단위 비교가 가능하다. | 동일 Node 사이의 parallel edge를 구분하지 못한다. |
| Epsilon 동률 비교 | 사람이 기대하는 근사 동률을 표현한다. | Comparator의 일관성과 Dijkstra 정렬을 깨뜨릴 수 있다. |
| Seed 기반 Random | 실행을 재현하면서 결과를 다양화할 수 있다. | 결정적인 최단 경로 알고리즘에 불필요한 변동성을 추가한다. |

## 다시 검토할 조건

- 거리 외에 회전 수나 혼잡도 같은 명시적인 2차 비용 정책을 도입하는 경우
- 거리 표현을 정수 또는 별도 value object로 변경하는 경우
- Path ID 목록 비교가 측정된 성능 병목이 된 경우
