# 003. Edge 거리를 명시적인 meter 값으로 표현

- 상태: 채택
- 결정일: 2026-08-10

## 맥락

Edge의 실제 이동 거리는 Node 사이의 직선거리와 다를 수 있다. 거리, 이동 시간, 혼잡 비용의 의미도 섞지 않아야 한다.

## 결정

Edge 생성 시 `distanceMeters: Double`을 명시적으로 입력한다. 값은 `0`보다 큰 유한값이어야 하며 Node 좌표로 자동 계산하지 않는다.

초기 Dijkstra는 Edge 거리의 합을 최소화한다. 차단된 Edge를 무한대 거리로 표현하지 않고 SimulationRun별 runtime state에서 통행 가능 여부를 관리한다.

| 값 | 처리 |
| --- | --- |
| 양수 유한값 | 허용 |
| `0`, 음수 | 거부 |
| `NaN`, 무한대 | 거부 |

## 선택의 장점

| 관점 | 장점 |
| --- | --- |
| 실제 통로 | 곡선, 우회, 회전 구간의 실제 이동 거리를 표현할 수 있다. |
| 좌표 분리 | 시각화 좌표를 바꿔도 routing 결과가 바뀌지 않는다. |
| 단위 | 이름에 meter를 드러내 단위 혼동을 줄인다. |
| 비용 의미 | 거리와 시간·혼잡 비용을 구분할 수 있다. |

## 감수하는 단점

| 단점 | 대응 |
| --- | --- |
| Edge마다 거리를 입력해야 한다. | 향후 편집 도구가 계산한 기본값을 제안하더라도 최종 거리는 명시적으로 저장한다. |
| `Double` 합산에는 오차가 생길 수 있다. | 누적값은 일관된 방식으로 비교하고 deterministic tie-breaking 규칙을 별도로 정한다. |
| 타입만으로 단위를 강제하지 못한다. | 거리 사용처가 늘어 단위 혼동이 생기면 `Distance` value object를 도입한다. |

## 검토한 대안

| 대안 | 장점 | 선택하지 않은 이유 |
| --- | --- | --- |
| 좌표 기반 자동 계산 | 직선 graph 입력이 간단하다. | 시각적 배치와 실제 이동 거리가 결합된다. |
| 일반적인 `cost` | 다양한 비용을 하나의 값으로 표현한다. | 거리, 시간, 혼잡도의 의미가 섞인다. |
| `Long` millimeter | 거리 합을 정수로 정확하게 계산한다. | 초기 좌표·속도 계산과 입력이 번거로워진다. |
| `Distance` value object | 단위와 유효성을 타입으로 보호한다. | 초기에는 사용처가 Edge 하나뿐이라 추가 타입과 연산이 과하다. |

## 아직 결정하지 않은 사항

- Node 좌표의 단위와 타입
- 거리 외의 시간·혼잡 cost 정책
- `Double` 동률 판단과 deterministic tie-breaking 규칙
- `Distance` value object 도입 시점

## 다시 검토할 조건

- 단위 혼동이나 중복 유효성 검사가 실제로 발생한 경우
- 정확한 소수 거리 합이 제품 요구가 된 경우
- 좌표 기반 거리 제안이 필요한 Map 편집 기능을 구현하는 경우
