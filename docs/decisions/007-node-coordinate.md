# 007. Node 좌표를 meter 단위의 2D 값으로 표현

- 상태: 채택
- 결정일: 2026-08-19

## 맥락

Node의 위치는 Map 시각화와 편집, 향후 Robot 위치 표현에 필요하다. 좌표는 화면상의 배치를 나타내며 실제 통로의 routing 거리와는 역할이 다르다.

## 결정

모든 Node는 필수 `Coordinate` value object를 가진다. `Coordinate`는 meter 단위의 `xMeters: Double`, `yMeters: Double`로 구성하며 외부 GIS 타입에 의존하지 않는다.

두 값은 모두 유한해야 한다. `0`과 음수는 허용하고 `NaN`과 양·음의 무한대는 거부한다. Node 좌표로 Edge 거리를 자동 계산하지 않는다.

서로 다른 `NodeId`를 가진 Node는 같은 좌표를 가질 수 있다. Node의 유일성은 ID로만 판단하고 좌표에는 고유성 제약을 두지 않는다.

| 항목 | 결정 |
| --- | --- |
| 타입 | `Coordinate` value object |
| 차원 | 2D |
| 필드 | `xMeters`, `yMeters` |
| 값 타입 | `Double` |
| 필수 여부 | 모든 Node에 필수 |
| `0`, 음수 | 허용 |
| `NaN`, 무한대 | 거부 |
| 서로 다른 Node의 동일 좌표 | 허용 |

## 선택의 장점

| 관점 | 장점 |
| --- | --- |
| 의미 | x와 y를 하나의 좌표 값으로 다룬다. |
| 단위 | 필드명에 meter를 명시한다. |
| 검증 | 좌표 유효성 규칙을 한곳에 모은다. |
| 계산 | 향후 meter 기반 Robot 속도와 자연스럽게 연결된다. |
| 독립성 | Domain core가 GIS와 PostGIS 타입에 의존하지 않는다. |
| 식별 분리 | ID는 Node를 식별하고 좌표는 위치만 표현한다. |

## 감수하는 단점

| 단점 | 대응 |
| --- | --- |
| 별도 value object가 추가된다. | 좌표의 단위와 검증을 보호하는 실제 domain 개념으로 사용한다. |
| 3D 또는 층을 직접 표현할 수 없다. | 여러 층 요구가 생기면 층과 높이의 의미를 구분해 확장한다. |
| 좌표만으로 실제 이동 거리를 알 수 없다. | Routing에는 Edge의 명시적인 `distanceMeters`를 사용한다. |
| 실수로 겹친 Node도 생성될 수 있다. | 향후 Map 편집 기능에서 경고하고 domain에서는 허용한다. |

## 검토한 대안

| 대안 | 장점 | 선택하지 않은 이유 |
| --- | --- | --- |
| Node에 x·y 직접 저장 | 별도 타입이 없어 단순하다. | 좌표의 단위와 검증 책임이 Node에 섞인다. |
| 3D 좌표 | 높이나 층을 함께 표현할 수 있다. | 층과 높이의 domain 의미가 아직 없고 초기 요구에 과하다. |
| GIS 또는 PostGIS Point | 실제 지리 정보와 공간 기능을 사용할 수 있다. | 실내 simulation 좌표에 과하며 core가 외부 기술에 종속될 수 있다. |
| 동일 좌표 Node 거부 | 입력 중복과 화면 겹침을 막기 쉽다. | 좌표가 두 번째 식별자 역할을 하고 같은 위치의 다른 routing 상태를 표현할 수 없다. |

## 다시 검토할 조건

- 실제 지리 좌표를 사용하는 외부 Map 연동 요구가 생긴 경우
- 여러 층이나 높이를 simulation에 포함해야 하는 경우
- 정수 기반 정밀도가 필요한 계산 요구가 생긴 경우
- 같은 좌표의 Node가 항상 입력 오류라는 강한 제품 제약이 생긴 경우
